# Translations and i18n

Mochifile is multilingual from day one. See [ADR 0007](../adr/0007-i18n-per-locale-urls.md).

## How it works

- **Locales** are declared in [`packages/i18n/src/index.ts`](../../packages/i18n/src/index.ts)
  and in `packages/i18n/project.inlang/settings.json` (a test keeps them in sync).
  Current locales: `en` (default) and `pt`.
- **URLs:** English at `/`, every other locale at `/<locale>/`. Build links with
  `localePath(locale, path)`; paths always end with `/`.
- **No automatic redirects** based on the browser language. People choose with the language
  switcher; search engines find the right page through `hreflang` links.
- **Messages** are JSON files compiled by [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs)
  into typed functions: `m.home_title({}, { locale })`. Always pass the locale explicitly.
  - Site messages: `packages/i18n/messages/<locale>.json`
  - Tool messages: `packages/tools/<id>/messages/<locale>.json`, listed in `pathPattern` of
    the inlang settings
- **Tool SEO metadata** (slug, title, description) lives in each tool's `manifest.ts`.

## Editing messages

1. Change the JSON files for **every** locale. Tests fail if keys differ between locales or a
   key is defined in two files.
2. Use `{name}` placeholders for variables: `"Download {name}"`.
3. Run `pnpm --filter @mochifile/i18n build` (or any root `pnpm build`/`pnpm dev`) to
   regenerate the typed functions.

Write for non-technical people: short sentences, everyday words, no jargon ("compress", not
"transcode"). Portuguese copy uses Brazilian Portuguese.

## Adding a locale

1. Add it to `locales` and `localeNames`/`localeTags` in `packages/i18n/src/index.ts` and to
   `locales` in the inlang settings.
2. Create the message files for the site and every tool.
3. Add `meta.<locale>` (slug, title, description) to every tool manifest.
4. Add `src/pages/<locale>/index.astro` and `src/pages/<locale>/[tool].astro` in `apps/web`.
5. Extend the e2e tests.
